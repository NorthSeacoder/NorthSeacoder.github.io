## v-if 和 v-for 哪个优先级更高?如果两个同时出现改如何优化

-   v-for 优先于 v-if 被解析
-   处理 ast 时会先看静态节点,然后是 once,for,if,children,slot
-   影响渲染函数的生成结果
-   如果同时出现,每次渲染都会先循环再判断条件,浪费性能
-   避免这种情况,外层套 template,在这一层用 v-if 判断,内部 v-for 循环

## vue 组件的 data 为什么必须是个函数而 vue 的根实例没有此限制

-   vue 组件可能存在多个实例,如果使用对象形式定义 data,会导致它们共用一个 data 对象,那么状态变更将会影响所有组件实例
-   采用函数形式定义,在 initDta 时会将其作为工厂函数返回全新 data 对象,避免多实例之间状态污染问题
-   根实例创建过程中不存在该限制,根实例只有一个
-   init 时会检测 data 的类型,是对象时会报错,但是,根实例合并选项的时后能取到实例对象,从而跳过这种检测

## vue 中 key 的作用和工作原理

-   key 的 作用主要是为了高效更新虚拟 DOM
-   原理是 vue 在 patch 过程中通过 key 可以精准判断两个节点是否是同一个,从而避免频繁更新元素,使得整个 pattch 过程更加高效,减少 DOM 操作量,提高性能
    -   头尾比较策略
    -   无 key 时,比较标签,是否注释,data 是否发生变化,是否相同的 input 类型

## vue 中的 diff 算法

diff 算法必要性

-   diff 算法通过新旧虚拟 DOM 作对比,将变化的地方更新在真实 DOM 上
-   vue(2) 中为了降低 Watcher 的粒度,每个组件只有一个相应的 watcher,只有通过 diff 算法才能精确找到发生变化的地方
-   diff 执行的时刻是组件实例执行其更新函数时,它会对比上一次渲染结果 oldvnode 和新的渲染结果 newVnode,此过程称为 patch

diff 算法执行方式

-   diff 过程整体遵循深度优先,同层比较的策略
-   两个节点之间比较会根据它们是否拥有子节点或者文本节点做不同的操作

高效性

-   头尾比较策略(头头,尾尾,头尾,尾头),如果没找到相同节点才切换为遍历,查找结束在按情况处理剩下的节点
-   借助 key 可以精准的找到相同节点

## 对 vue 组件化的理解

定义

-   组件是独立和可复用的代码组织单元,用分治的思想来编写代码

优点

-   组件化开发能大幅提高应用的开发效率,测试性,复用性

使用场景

-   组件按使用分类有:页面组件,业务组件,通用组件
-   页面组件:路由组件
-   业务组件:登录等与业务强相关的组件
-   通用组件:按钮...

组件化的特点

-   vue 的组件是基于配置的,平时写的组件都是组件配置,vue 后续会基于 VueComponent 生成其构造函数,
-   vue 中常见的组件化技术:属性 props,自定义事件,插槽等,主要应用于组件间通信,扩展

注意事项

-   合理划分组件,有助于提升应用性能(一个组件对应一个 Watcher)
-   组件应是高内聚,低耦合
-   遵循单项数据流原则

## 对 mvc mvp mvvm 的理解

-   mvc:

    -   model:负责保存应用数据,与后端数据同步
    -   controller:负责业务逻辑,根据用户行为对 model 数据进行修改
    -   view:负责视图展示,将 model 中的数据展示出来

-   mvvm:

    -   model:负责保存应用数据,与后端数据同步
    -   view:负责视图展示,将 model 中的数据展示出来
    -   viewmodel:通过响应式吉致自动响应 model 中的数据变化,自动更新视图

-   这三者都是框架模式,他们设计的目标都是为了解决 model 和 view 耦合的问题
-   mvc 模式出现于后端,前端早起也有应用,优点是分层清晰,缺点是数据流混乱
-   mvp 是 mvc 的优化,Presenter 作为中间层负责 mv 通信,解决了两者的耦合问题,但 p 层过于臃肿会导致维护问题
-   mvvm 应用更为广泛,不仅解决了 mv 耦合问题,还解决了维护两者映射关系的大量繁杂代码和 dom 操作代码,提高开发效率,可读性听同事还保持了优越的性能表现

## vue 基础

### 双向数据绑定的原理

-   根据 Data 变化更新 View。
    -   实现一个监听器 Observer ，用来劫持并监听所有属性，如果属性发生变化，就通知订阅者
    -   实现一个订阅者 Watcher，可以收到属性的变化通知并执行相应的方法，从而更新视图；
    -   实现一个订阅器 Dep，用来收集订阅者，对监听器 Observer 和 订阅者 Watcher 进行统一管理；
    -   实现一个解析器 Compile，可以解析每个节点的相关指令，对模板数据和订阅器进行初始化。
-   View 变化更新 Data ，可以通过事件监听的方式来实现

### slot 的实现原理

-   当子组件 vm 实例化时，获取到父组件传入的 slot 标签的内容，存放在 vm.$slot中，默认插槽为vm.$slot.default，具名插槽为 vm.$slot.xxx，xxx 为插槽名，当组件执行渲染函数时候，遇到slot标签，使用$slot 中的内容进行替换，此时可以为插槽传递数据，若存在数据，则可称该插槽为作用域插槽。

### 对 keep-alive 的理解，它是如何实现的，具体缓存的是什么

-   keep-alive 是个抽象组件,它自身不会渲染一个 DOM 元素，也不会出现在父组件链中。
-   LRU 缓存策略
-   三个属性
    -   includes
    -   excludes
    -   max
-   流程
    -   判断组件是否需要缓存,不需要的话直接返回 vnode
    -   利用组件的 key 去缓存中查询组件是否存在(key:cid::tag)
    -   存在则从缓存中获取组件,并删除旧缓存,重新添加
    -   不存在时先保存组件和 key,updated 时添加到缓存中
    -   当缓存数量超过 max 时,删除缓存中第一个组件

### nextTick 原理

-   nextTick 中的回调是在下次 DOM 更新循环结束之后执行的延迟回调。在修改数据之后立即使用这个方法，获取更新后的 DOM。
-   主要思路就是采用微任务优先的方式调用异步方法去执行 nextTick 包装的方法

### vue 与 react 的异同

-   相同点:
    -   功能拆分,路由/状态管理交给别的库
    -   有自己的构建工具
    -   都使用了虚拟 dom
    -   都有 props 的概念用于组件间传值
    -   都鼓励组件化应用
-   不同点:
    -   数据流:Vue 默认支持数据双向绑定，而 React 一直提倡单向数据流
    -   虚拟 dom:
        -   vue 渲染过程中会跟踪每个组件的依赖关系,不需要渲染整颗组件树
        -   React 每当应用的状态被改变时，全部子组件都会重新渲染,可以设置
    -   组件化:vue 鼓励写 template,react 鼓励 jsx
    -   扩展方式:vue:mixin,react:hoc

### Vue 子组件和父组件执行顺序

-   加载渲染过程：
    -   父组件 beforeCreate
    -   父组件 created
    -   父组件 beforeMount
    -   子组件 beforeCreate
    -   子组件 created
    -   子组件 beforeMount
    -   子组件 mounted
    -   父组件 mounted
-   更新过程：
    -   父组件 beforeUpdate
    -   子组件 beforeUpdate
    -   子组件 updated
    -   父组件 updated
-   销毁过程：
    -   父组件 beforeDestroy
    -   子组件 beforeDestroy
    -   子组件 destroyed
    -   父组件 destoryed

### 路由的 hash 和 history 模式的区别

-   Vue-Router 有两种模式：hash 模式和 history 模式。默认的路由模式是 hash 模式。
-   hash 模式原理:onhashchange()事件
-   history 模式原理:history.pushState()
-   区别:
    -   pushState() 设置的新 URL 可以是与当前 URL 同源的任意 URL；而 hash 只可修改 # 后面的部分
    -   pushState() 设置的新 URL 可以与当前 URL 一模一样，这样也会把记录添加到栈中；而 hash 设置的新值必须与原来不一样才会触发动作将记录添加到栈中；
    -   history 模式下,后端需要单独设置,否则会出现 404 页面

### $route 和$router 的区别

-   $route 是“路由信息对象”，包括 path，params，hash，query，fullPath，matched，name 等路由信息参数
-   $router 是“路由实例”对象包括了路由的跳转方法，钩子函数等。
