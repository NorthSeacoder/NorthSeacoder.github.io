## http 和 https 的基本概念

### http

-   超文本传输协议
-   应用最为广泛的网络协议
-   客户端和服务器端请求和应答的标准
-   用于从 服务端传输超文本到客户端的传输协议

### https

-   http 下加入 SSL 层用以加密

## http 和 https 的区别

| 区别 |    http     |                               https                               |
| :--: | :---------: | :---------------------------------------------------------------: |
| 费用 |             |                         额外申请 ca 证书                          |
| 端口 |     80      |                                443                                |
| 连接 | 无状态连接  |      由 SSL+HTTP 协议构建的可进行加密传输身份认证的网络协议       |
| 加密 | 明文,不安全 | 机密性(AES 对称加密)/完整性(摘要算法)/身份认证(RSA)/不可否认(RSA) |
| 协议 |   TCP/IP    |                              SSL/TLS                              |
| 性能 |    流畅     |                     加密解密有一定的性能消耗                      |

## https 的通信流程(工作原理)

-   客户端使用 https url 访问服务器,要求 web 服务器建立 ssl 连接
-   web 服务器接受请求后会将网站证书(包含公钥)返回给客户端
-   客户端和服务端协商 SSL 连接的安全等级(加密等级)
-   建立会话密钥,客户端通过网站公钥加密并传输给服务器端
-   服务器端通过私钥解密出会话秘钥
-   服务器端通过会话秘钥加密与客户端之间的通信

## https 的优点

-   使用 HTTPS 协议可认证用户和服务器,确保数据发送正确
-   保证数据完整性(保证数据传输过程中不被窃取,改变)

## https 的缺点

-   握手阶段耗时.会使页面加载时间延长 50%,增加 10%-20% 的耗电(仅指初次建立连接时)
-   缓存不如 http 高效,会增加数据开销
-   SSL 证书越强大越贵
-   SSL 证书需要绑定 IP,无法一个 IP 上绑定多个域名,ipv4 支持不了这种消耗(但通过子域名通配符 SSL 证书可以支持一个 IP 上部署多个 https 子域名)

### 加载时间延长原因

-   http 使用 tcp 三次握手,只需交换 3 个包,https 除了 tcp 的 3 个包还有 ssl 的 9 个包

## 常见状态码

-   1xx:提示信息,表示目前是协议处理的中间状态,还需后续操作
-   2xx:成功,报文收到并被正确处理
-   3xx:重定向,资源位置发生变动,需要客户端重新发送请求
-   4xx:客户端错误,请求报文有误,服务器无法处理
-   5xx:服务器错误,服务器在处理请求时内部发生错误

## http 的特点

-   灵活可扩展的协议
-   "可靠"的传输协议
-   应用层协议
-   请求应答的通信模式
-   无状态的:状态就是客户端或者服务器里薄脆的一些数据或标志,记录了通信过程中的变化信息,TCP 有状态,CLOSED 等等,需要 TCP 内部用数据结构去维护

## http 的优缺点

-   简单灵活易于扩展
-   应用广泛,环境成熟
-   无状态(也是缺点)
    -   不需要额外的资源来记录状态信息,减轻服务器负担
    -   负载均衡操作简单,轻松实现高并发高可用
    -   不支持需要多个步骤的事务操作(比如登录,后续一系列操作都需要确认身份信息)(利用 cookie 实现有状态)
-   明文传输(也是缺点)
-   不安全(身份认证,完整性校验)
-   性能,不差,但也不适合现在

## http/2 的特点

-   兼容 HTTP/1.0:将 http 分解为语义和语法两个部分,语义层不做改动如请求方法/URI/状态码/头字段.语法层则完全变更了 http 报文的传输格式
-   消除了应用层的队头阻塞(TCP 是传输层)
-   头部压缩:"HPACK"算法在客户端服务端建立索引表,用索引号表示重复的字符串,哈夫曼编码来压缩整数和字符串
-   二进制格式报文:将"Hader+Body"打散为数个小片的二进制帧
-   虚拟流:二进制帧的双向传输序列,帧利用流 id 确定所属流
-   多路复用:帧在流中是严格有序的,在连接上则是乱序的,所以可以在一个连接上发送多个碎片化的消息
-   服务器推送:服务器可以新建流主动向客户端发消息
-   强化安全:底层要求至少是 TLS1.2,禁用了很多不安全对的密码套件

## 输入 URL 到页面渲染的整个过程

-   输入 url:浏览器判断是否为网址,不是的话将内容和默认搜索引擎合成新的 url
-   构建请求:浏览器构建请求行信息,通过进程间通信将 url 请求发送给网络进程
-   查找本地缓存,有则拦截请求
-   DNS 解析:
    -   浏览器缓存->操作系统缓存->本地 hosts 文件->非权威域名服务器->根域名服务器(获取.com 地址)->顶级域名服务器(获取 apple.com 地址)->二级域名服务器
    -   解析域名对应的 IP 和端口号,未指定端口号则选择默认(http:80,https:443),如果是 https 还需要建立 TLS 连接
-   等待 tcp 队列:chrome 机制,一个域名同时最多只有 6 个 TCP 连接
-   建立 TCP 连接
-   发起 HTTP 请求:发送请求行(方法,uri,http 协议版本)
-   服务器处理请求,返回信息(比如返回一个 html)
-   断开连接(长链接会保持连接)
-   构建 dom 树
-   样式计算:
    -   外部引入样式转化成浏览器能理解的结构
    -   转换样式表中的属性值
    -   根据 css 继承和层叠规则计算出 dom 每个节点的具体样式
-   布局:
    -   生成一颗只包含课件元素的布局树,
    -   根据布局树的每个节点计算出其具体位置和尺寸
-   分层:
    -   为一些有复杂效果的节点生产专用的图层
-   绘制:为每个图层生成回执表,提交到合成线程
-   光栅化:合成线程优先合成视口附近的图块来生成位图,在光栅化线程池中将图块转换成位图
-   合成:一旦所有图块都被光栅化,合成线程会生成一个绘制图块的命令 DrawQuad,并将该命令提交给浏览器进程,最后生成页面
